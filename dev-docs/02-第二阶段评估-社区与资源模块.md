# 第二阶段评估方案:社区/资源模块与封闭化改造

> 目标:把当前 LobeChat 白标部署改造为像腾讯 WorkBuddy 那样的**封闭式 C 端客户端产品**——技能(skill)/助手(agent)由开发者(你)开发后供给用户,不依赖 lobehub 开放社区市场。
> 前提:不影响产品正常运行。
> 依据:3 个 Explore agent 全量调研(社区模块全貌 / lobehub 链接排查 / 内容供给链)。

---

## 一、现状全貌

### 1.1 社区/市场/发现模块地图

| 模块 | 路径/入口 | 用途 | 数据源 | lobehub 依赖 |
|---|---|---|---|---|
| **社区市场(桌面)** | `src/routes/(main)/community/`(list+detail:agent/mcp/skill/model/provider/group_agent/org/user) | 浏览/搜索/安装 lobehub 社区市场内容 | `discoverService.*` → 自托管后端 `routers/lambda/market/*` → `@lobehub/market-sdk` → `market.lobehub.com` | **强** |
| **社区市场(移动)** | `src/routes/(mobile)/community/` | 同上移动版 | 同上 | **强** |
| **SkillStore 弹窗** | `src/features/SkillStore/`(3 Tab) | 技能/工具商店 | LobeHub Tab=lobehub 云执行(connected apps);Skills/MCP Tab=lobehub 市场;Builtin/Custom Tab=**本地** | LobeHub/Skills/MCP 强;Builtin/Custom 无 |
| **Onboarding** | `src/routes/onboarding/`、`(desktop)/desktop-onboarding/` | 引导选助手 | `fetchOnboardingAgentTemplates` → lobehub 模板 | **强**(模板) |
| **MarketAuth/OIDC** | `src/layout/AuthProvider/MarketAuth/`、`src/app/(backend)/market/oidc/`、`src/libs/oidc-provider/config.ts` | 与 lobehub 市场建立 OIDC 身份(fork/社交/认领) | 直连 lobehub | **强** |
| **资源库(本地)** | `src/routes/(main)/resource/` | 文件管理 + 知识库(RAG) | 本地 DB + S3(RustFS) | **无** |
| **对话核心** | `src/store/chat`、`session`、`features/Conversation` | 聊天 | 本地 DB(agent/skill) | **无(运行时)** |

### 1.2 关键发现(决定方案走向)

1. **社区入口已被 `showMarket` 特性开关门控**:`useNavLayout.ts:83 hidden: !showMarket`、`MobileTabBar:47 showMarket &&`。**设 `showMarket=false` 即可零代码隐藏侧栏/底栏的社区入口**。`showMarket` 是服务端下发的 feature flag(`serverConfig.featureFlags.showMarket`),源在 `apps/server/src/globalConfig/index.ts:110-114` 的 `enableMarketTrustedClient`/`enableLobeHubSkill`。
2. **`/resource` 是本地功能(文件+知识库),与 lobehub 市场无关,保留**。不要与 community 混淆。
3. **对话与市场是弱耦合**:chat 运行时只读本地 DB 的 agent/skill,不实时拉市场。市场仅喂"安装"步骤。**移除市场浏览不影响已安装 agent/skill 的使用**。
4. **唯一的运行时 lobehub 依赖**:LobeHub connected-app Skills(GitHub/Linear/Notion 等工具的实际调用走 lobehub 云执行 `connectCallTool`)。若用户 agent 配了这类工具,断开 lobehub 会使这些工具在对话中报错(仅影响这些特定工具,不崩对话)。
5. **自托管后端是一层薄代理**:`apps/server/src/routers/lambda/market/*` + `MarketService`/`DiscoverService` 只是给 lobehub 市场 API 加鉴权/token/遥测,底层数据全来自 `market.lobehub.com`(`MARKET_BASE_URL` env,默认 lobehub)。**这套骨架可复用为"开发者内容供给后台"**(把 `MARKET_BASE_URL` 指向你的服务,或让 `MarketSDK` 换成本地 DB 查询)。
6. **`marketApiService` 已有"开发者自有 agent 管理"能力**:`createAgent`/`getOwnAgents`/`createAgentVersion`/`deprecateAgent` 等——正是封闭式"开发者供给"需要的后端,可保留改造。

### 1.3 lobehub 链接排查(全项目)

**直接清空会破坏功能(需替换值或禁用功能)**:
- `market.lobehub.com`(社区市场 API,多处)。
- `web-assets.lobehub.com`(**移动端 SPA 模板**:mobileHtmlTemplate.source.ts 硬编码从这拉 mobile JS/CSS/i18n bundles——移动 web 全靠它)。
- `device-gateway.lobehub.com`(设备配对/同步,CLI/桌面默认)。
- `app.lobehub.com`(CLI/桌面云模式默认服务端)。
- `chat-plugins.lobehub.com`(插件索引)。
- `app://lobehub.com`(Electron 内部协议 scheme)。

**清空只死链接不崩的(可安全置空)**:
- 所有 `OFFICIAL_SITE`/`OFFICIAL_URL`/`DOCUMENTS`/`BLOG`/`PRIVACY_URL`/`TERMS_URL`/`CHANGELOG_URL`/`MANUAL_UPGRADE_URL`/`BASE_PROVIDER_DOC_URL`/`AGENTS_OFFICIAL_URL`/`DOWNLOAD_URL.*` 的 UI 链接(关于页/版本/changelog/设置 provider 文档/社区 sidebar ActionButton/下载页/auth 页脚/onboarding 遥测/用户面板/分享页/横幅等)。
- `hub-apac-1.lobeobjects.space` CDN 资源(教学视频 notio.mp4、skill 图标、OIDC logo、changelog 图等)→ 会 404,需自托管替换。
- 邮箱(`hello@lobehub.com`/`support@lobehub.com`/`hi@lobehub.com` 在多处 UI + locale)、社交 URL(medium/x/youtube)、locale 字符串(`subscription`/`discover`/`setting` 里的 lobehub 邮箱/链接)、HTTP-Referer 头(openrouter/togetherai/higress/vercelaigateway)、bot 平台 setup guide 链接、discover 生成的 homepage URL。
- 桌面端 Help 菜单硬编码 `lobehub.com` + `github.com/lobehub`(3 个平台文件)。

**已是本地/安全的**:OG 图(`public/og/*.webp`)。

### 1.4 内容供给链(agent/skill/plugin)

| 类型 | 内置(builtin 包) | 用户自建(本地 DB) | 市场(lobehub) | 开发者注入通道 |
|---|---|---|---|---|
| Agent | `packages/builtin-agents/`(12 个:inbox/agent-builder/...),`BUILTIN_AGENTS` 注册,virtual,惰性建 `agents` 表行 | `agents` 表(userId+workspaceId) | `market.lobehub.com`(MarketSDK)→ 安装带 `marketIdentifier` 的 `agents` 行 | **通道A:builtin-agents 包加文件**(自动注册,但 virtual 不在普通列表,需补入口) |
| Skill | `packages/builtin-skills/`(4 个:agent-browser/artifacts/lobehub/task) | `agent_skills` 表 source='user' | `importFromMarket` 从 lobehub 下载 zip | **通道B:builtin-skills 包加文件**(自动在 SkillStore「LobeHub」标签对所有人可见,改动最小) |
| Tool | `packages/builtin-tools/`(25+ 个),`builtinToolRegistry` 注册 | — | 插件市场 + MCP | **通道C:builtin-tools 包加文件**(需前后端配套 executor) |
| MCP/Connector | — | `user_connectors` 表(本地,stdio/http/cloud MCP) | 社区 MCP 列表(可移除),自建独立 | 自建 connector 不依赖市场 |
| Plugin(legacy) | — | `user_installed_plugins`(customPlugin) | 插件市场 | — |

**关键结论**:**无现成"系统/官方 agent"机制**(`systemBotProvider` 只是 messenger bot 凭证表,非 agent 供给)。开发者注入自有内容走 builtin-* 包机制(全自动注册,所有用户可用)。

## 二、各模块评估:保留 / 移除 / 改造

| 模块 | 建议 | 依据 | 对运行影响 |
|---|---|---|---|
| `/resource`(文件+知识库) | **保留** | 本地功能,与市场无关 | 无 |
| 对话 chat / 本地 agent CRUD / 内置 agent&skill&tool / MCP connector / 自定义 skill 导入 | **保留** | 全本地自洽,不依赖市场 | 无 |
| 社区入口(侧栏/底栏) | **隐藏**(showMarket=false) | 已有开关,零代码隐藏;先跑起来 | 无(导航少一项) |
| `/community` 路由(浏览/安装 lobehub 市场) | **改造 or 删**(见决策点) | 与封闭式冲突;前端可复用为自有商店 | 隐藏入口后用户进不去,不影响已装内容 |
| SkillStore - Builtin/Custom Tab | **保留** | 本地供给,与目标一致 | 无 |
| SkillStore - LobeHub/Skills/MCP Tab | **改造 or 删**(见决策点) | 浏览/安装 lobehub 市场 | connected-app(LobeHub Tab)是唯一运行时市场依赖 |
| Onboarding 选助手 | **改造**(改接本地模板)or 移除该步 | 现拉 lobehub 模板 | 引导失败可降级跳过 |
| MarketAuth/OIDC | **改造 or 删** | fork/社交/认领依赖 lobehub 身份 | 纯浏览可走 M2M/trusted-client;删则不能 fork |
| `marketApiService` 开发者 agent 管理(createAgent/getOwnAgents/...) | **保留并改造** | 正是封闭式开发者供给后端 | 无(改造复用) |
| 自托管 market 后端代理(`routers/lambda/market`+MarketService/DiscoverService) | **保留骨架,改造指向** | 可复用为开发者内容供给后台(MARKET_BASE_URL 指自有服务 or 换本地 DB) | 无 |
| `lobe-skill-store` 内置 tool(alwaysOn,搜市场 skill) | **改造** | 现调 MarketService.searchSkill | 改为搜本地内置 skill 列表 |
| `aiAgent` 服务的 `marketService`(LobeHub skill manifest) | **改造** | 获取 LobeHub skill 服务 manifest | 替换为内置 manifest or 移除该集成 |
| lobehub.com 死链接 UI(about/docs/terms/privacy/下载 等) | **清空或替换** | 清空只死链接不崩 | 无(等用户给域名统一替换更好) |
| `lobeobjects.space` CDN 资源(视频/图标/logo) | **自托管替换** | 404 替换 | 无 |
| 移动端 SPA 模板(`web-assets.lobehub.com`) | **决策**(见决策点) | 移动 web 全靠它 | 不支持移动 web 则可忽略 |
| `device-gateway`/`app.lobehub.com`(CLI/桌面云默认) | **改 env 默认 or 不用** | CLI/桌面云模式 | web 用户不受影响;桌面/CLI 用户需指向自有 |

## 三、推荐路线(分阶段,由低风险到深度)

### 阶段 2a:快速封闭化(低风险,先跑起来)
1. **隐藏社区入口**:设 `showMarket=false`(服务端 feature flag / globalConfig),侧栏/底栏 community 项消失。零代码。
2. **清空 lobehub 死链接 UI**:`url.ts`/`branding.ts` 里 OFFICIAL_*/DOCUMENTS/BLOG/PRIVACY/TERMS/CHANGELOG/DOWNLOAD/AGENTS_OFFICIAL/BASE_PROVIDER_DOC 等置空(死链接,不崩);社交 URL(medium/x/youtube)置空;邮箱留待用户给。
3. **自托管 CDN 资源**:把 `lobeobjects.space` 的视频/图标/logo 拷贝到 `public/` 并改引用,或暂置空。
4. **桌面 Help 菜单**:删 lobehub/github 项(3 平台文件)。
5. **移动端 SPA 模板**:若暂不支持移动 web,可不管(不影响桌面 web)。
6. 验证:对话/生图/设置(仅 newapi)/资源库 全部正常。

### 阶段 2b:内容供给切换(开发者注入自有内容)
1. **用 builtin-* 包注入你的 agent/skill/tool**:
   - Agent:`packages/builtin-agents/src/agents/<your-agent>/` 加文件 + 注册 `BUILTIN_AGENT_SLUGS`/`BUILTIN_AGENTS`;若要进用户列表,小改 `queryAgents` 过滤。
   - Skill:`packages/builtin-skills/src/<your-skill>/` 加文件 + 入 `builtinSkills` 数组(自动对所有人可见)。
   - Tool:`packages/builtin-tool-<your>/` 加包 + `builtinToolRegistry` 注册 + server executor。
2. **SkillStore 改造**:只保留 Builtin/Custom Tab(本地);隐藏/移除 LobeHub/Skills/MCP 市场 Tab(或改造指向你的供给)。
3. **Onboarding 改造**:选助手步骤改接本地 builtin agent 模板(或跳过)。
4. **`lobe-skill-store` tool 改造**:`searchSkill`/`importFromMarket` 改为搜本地内置 skill 列表。
5. **`aiAgent` marketService 改造**:LobeHub skill manifest 替换为内置 manifest or 移除。

### 阶段 2c:深度清理(可选,彻底封闭)
1. **删社区路由/代码**:`src/routes/(main)/community/`、`(mobile)/community/`、`src/store/discover/`、`src/services/discover.ts`+`marketApi.ts`、`src/layout/AuthProvider/MarketAuth/`、`src/app/(backend)/market/`、`apps/server/src/routers/lambda/market/`、`apps/server/src/routers/tools/market.ts`(拆分保留非市场部分如 MCP 执行)。
2. **market 后端改造为开发者供给后台**:复用 `MarketService`/`DiscoverService` 骨架 + `marketApiService` 的 createAgent/getOwnAgents,把 `MARKET_BASE_URL` 指向你的供给服务 or 换成本地 DB 查询;`/community` 前端复用为"你的官方助手/技能商店"。
3. **connected-app Skills 决策落地**:自建等价执行层 / 改走 MCP / 移除(见决策点)。
4. **lobehub.com 非 GitHub 链路**:用户给域名后统一替换 OFFICIAL_SITE/URL/terms/privacy/subscription/email 等。
5. **移动端 SPA**:若要支持,自托管 mobile bundles;否则确认不做移动 web。

## 四、需用户拍板的决策点

1. **社区市场处置策略**(决定 2b/2c 走向):
   - A 快速隐藏(showMarket=false,保留代码备用)——最快最低风险。
   - B 改造成"你的官方内容专区"(复用 /community 前端,MARKET_BASE_URL 指你的供给服务或换本地 DB)——WorkBuddy 式"开发者供给商店"。
   - C 彻底删社区代码——最干净但失复用选项+工作量大+风险。
2. **LobeHub connected-app Skills(GitHub/Linear 等,唯一运行时市场依赖)**:保留(需自建执行层或仍连 lobehub)/ 移除 / 改走 MCP。
3. **lobehub.com 非 GitHub 链路(official-site/docs/terms/privacy/subscription/email)**:现在清空成死链接 vs 等你给域名统一替换。
4. **移动端 SPA(web-assets.lobehub.com)**:需要支持移动 web 吗?(否→忽略;是→需自托管 bundles)
5. **Onboarding**:保留引导但改接本地助手模板 vs 移除引导步骤。
6. **桌面端/CLI 云默认(device-gateway/app.lobehub.com)**:你是否做桌面/CLI 客户端?(否→不用动;是→改 env 默认指向自有)

## 五、风险与边界(不影响运行的前提)

- 阶段 2a 全部低风险(隐藏入口 + 清死链接 + 自托管资源,不动核心)。
- 阶段 2b 的 `lobe-skill-store`/`aiAgent marketService` 改造需小心(中风险),但对话核心不依赖。
- 阶段 2c 删代码风险最高,建议在 2a/2b 稳定后做,且逐个删、每步 typecheck+点验。
- **始终不动**:`/resource`、对话核心、newapi runtime、builtin-* 已有内容、MCP connector 自建、自定义 skill 导入。
