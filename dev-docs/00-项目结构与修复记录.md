## 二、关键子系统详解

### 2.1 图片模型参数 schema(model-bank)

`packages/model-bank/src/const/imageParameters.ts` 定义每个图片模型的 UI 参数 schema:

- `gptImage1Schema` —— gpt-image-1,`size`(分辨率)。
- `gptImage2Schema` —— gpt-image-2 原生 API,**`size` 分辨率**(`1024x1024`/`2048x2048`…)。
- `gptImage2AspectRatioSchema` —— **本次新增/启用**。面向 OpenAI 兼容网关(如 newapi)的 gpt-image-2,用 `aspectRatio`(比例字符串 `16:9` 等)而非分辨率。
- `nanoBanana*` 系列 —— Gemini 系,`aspectRatio` + `resolution`。

这些 schema 通过 `packages/model-bank/src/aiModels/index.ts` 的 barrel 导出,供 `model-runtime` 以 `from 'model-bank'` 引入。

### 2.2 newapi provider 运行时(model-runtime)

`packages/model-runtime/src/providers/newapi/index.ts` 导出 `params`(满足 `CreateRouterRuntimeOptions`):

- `params.models({client, options})` —— 异步拉取网关模型列表 + pricing,拼装后交给 `processMultiProviderModelList(list, 'newapi')`。**这是"拉取模型"同步的入口,也是参数被覆盖的现场。**
- `params.routers(options, runtimeContext)` —— 按 apiType 路由(anthropic/google/xai/deepseek/openai),各自重写 `baseURL`。

`createRouterRuntime(params)` 产出最终 `LobeNewAPIAI`。

### 2.3 模型列表通用 enrichment 管线(modelParse.ts)

`packages/model-runtime/src/utils/modelParse.ts` 的 `processMultiProviderModelList` / `detectModelProvider` / `findKnownModelByProvider` / `processModelCard` 是**跨 provider 通用**的:

- 按**模型 ID 关键字**(如 `openai: ['o1','o3','gpt-']`)**不区分实际 providerId** 地匹配内置 provider 卡片;
- 在 `parameters: model.parameters ?? knownModel?.parameters`(约 `modelParse.ts:646`)处用匹配到的卡片 `parameters` 兜底——**只要原始 model 对象已自带 `parameters`,就不会被卡片覆盖**。这是本次持久修复所依赖的优先级规则。

### 2.4 图片生成运行时(createImage.ts)

`packages/model-runtime/src/core/openaiCompatibleFactory/createImage.ts` 的 `generateByImageMode`:

- 通过 `paramsMap` 把 UI 参数名映射到 OpenAI API 字段:`aspectRatio → size`、`imageUrls/imageUrl → image`(网关如 newapi 的 gpt-image-2 在同一个 `size` 字段里接收比例字符串)。
- 区分 generate/edit;`size === 'auto'` 时删除该字段;gpt-image-1 family 加 `input_fidelity: 'high'`(mini 除外)。
- 返回 `b64_json` 或 `url`;**注意:此路径不调用 `handleError`**,故 OpenAI SDK 抛出的原生 `TypeError: Invalid URL` 不会被错误归一化层捕获——这就是"Invalid URL"报错直接外溢的原因。

### 2.5 数据库:provider 与模型两层

- `ai_providers`(provider 级):含 `enabled`、`key_vaults`(加密)。**provider 级 `enabled` 与模型级 `enabled` 是两张表上的两列,互不替代。**
- `ai_models`(模型级):含 `enabled`、`parameters`(jsonb)、`source`(`builtin`/`remote`/`custom`/`NULL`)。前端 `enabledImageModelList` 直接用 DB 里的 `parameters`,覆盖 model-bank 静态 schema。
- `key_vaults` 加密:`apps/server/src/modules/KeyVaultsEncrypt/`,AES-256-GCM,格式 `ivHex:tagHex:cipherHex`,密钥由 `KEY_VAULTS_SECRET`(base64)解码得 16/24/32 字节。解密后 JSON 形如 `{apiKey, baseURL}`。

### 2.6 图片生成端到端流程

```
UI 选模型+参数(aspectRatio)
  → tRPC → server → runtime(newapi)
  → createOpenAICompatibleImage → paramsMap: aspectRatio→size
  → OpenAI SDK client.images.generate/edit
  → 网关(baseURL + /v1/images/...)  → 返回 b64_json/url
  → 上传 S3(RustFS)→ 前端展示
```

任一环出错都会外溢:baseURL 空 → `Invalid URL`;S3 凭据不匹配 → `Access Key Id … does not exist`;网关不认分辨率 → `400 Invalid size, allowed ratios: ...`。

## 三、优化与修复记录(第一阶段排障)

> 原则:每个问题都先**直接取证**(解密/查库/查容器环境)再动手,避免盲改;尤其因早期发生过整目录 Finder 清空丢失,对数据/配置格外谨慎。

### 修复 1:newapi 服务商在设置页不显示

- **现象**:Settings 里看不到 newapi 服务商。
- **根因**:`ai_providers.enabled`(provider 级)为 `false`。provider 级 `enabled` 与 `ai_models.enabled`(模型级)是不同表不同列,此前只开了模型级、未开 provider 级。
- **修复**:`UPDATE ai_providers SET enabled = true WHERE id='newapi' AND user_id=<uid>;`
- **验证**:SELECT 确认 `enabled = t`,设置页可见。

### 修复 2:生图报错 `Invalid URL`

- **现象**:用 newapi/gpt-image-2 生图直接抛 `TypeError: Invalid URL`。
- **根因**:解密 `ai_providers.key_vaults` 后 `baseURL` 为空字符串 `""`。OpenAI SDK `buildURL` 执行 `new URL(baseURL + path)`,空 baseURL 抛原生 `TypeError`,而 `createImage.ts` 路径无 `handleError` 兜底,故直接外溢。
- **取证手段**:临时脚本 `scripts/tmp-decrypt-keyvaults.ts`(Node `webcrypto` + `pg`,输出时 mask apiKey)解密确认 `{"apiKey":"sk-L**(len51)","baseURL":""}`,用完即删。
- **处置**:属**用户配置**问题——Base URL 字段为空。我无法获知用户私有网关地址,已请用户在 Settings 填正确 Base URL。未做代码/DB 改动。

### 修复 3:生图报错 `The Access Key Id you provided does not exist in our records.`

- **现象**:填好 baseURL 后再生图,S3 上传报 Access Key Id 不存在。
- **根因**:`lobe-rustfs` 容器创建早于 `.env` 写入自定义凭据(`9b2a…`/`3407c…`);Docker **不回溯**应用 `.env` 变更到已运行容器,容器仍在用镜像默认凭据(`admin`/`change_this_password_on_production`)。
- **取证**:`docker inspect` 对比容器实际环境变量与 `.env` 文件,确认不一致;compose 文件本身(`docker-compose/dev/docker-compose.yml` 第 56-94 行)wiring 正确,排除其作为源头。
- **修复**:`docker compose -f docker-compose/dev/docker-compose.yml up -d --force-recreate rustfs`(命名卷 `rustfs-data` 保留,数据不丢)。
- **验证**:`docker inspect` 显示新凭据;`curl http://localhost:9000/health` → `200`;healthcheck `healthy`。
- **附记**:校验脚本里用 `status` 作循环变量触发 `zsh: read-only variable: status`——zsh 把 `status` 当保留变量名,改名 `health` 解决。

### 修复 4(重点):gpt-image-2 尺寸选择器回退成"分辨率"

- **现象**:用户反馈"又把 gpt-image-2 模型选择图片尺寸改成了分辨率,这是不对的,image2 模型生图的尺寸是按照比例选择的"。
- **根因取证**:直接查库 `SELECT provider_id, id, parameters FROM ai_models WHERE id='gpt-image-2';`,确认 `newapi` 行 `parameters` 已变回 openai 的分辨率 schema(与 `openai` 行逐字节相同)。**不是本次手动改坏,而是一个无关后台机制所致:**
  - Settings 的"拉取模型"按钮触发 `newapi/index.ts` 的 `models()` 同步;
  - 同步经 `processMultiProviderModelList` 这条**跨 provider 通用**管线,按 ID 关键字(`gpt-`→openai)匹配内置卡片,以其 `parameters` 兜底;
  - `AiModelModel.batchUpdateAiModels`(`packages/database/src/models/aiModel.ts`)的 upsert 仅在已存在行 `source='builtin'` 时保留原 `parameters`;**newapi 模型行永远非 `builtin`**(newapi 无静态卡片),故每次"拉取模型"都会把自定义比例 schema 静默换成 openai 分辨率 schema。
  - 这也解释了上次只改 DB 未能持久的原因——纯 DB 改动在下一次"拉取模型"时会被再次覆盖。
- **持久修复(代码层,3 处)**:
  1. `packages/model-bank/src/aiModels/index.ts`:把此前未导出的 `gptImage2AspectRatioSchema` 加入公共 barrel 导出。
  2. `packages/model-runtime/src/providers/newapi/index.ts`:从 `model-bank` 引入 `gptImage2AspectRatioSchema`;新增 `MODEL_PARAMETERS_OVERRIDES` 映射(`'gpt-image-2' → gptImage2AspectRatioSchema`);在 `models()` 把 `combinedModelList` 交给 `processMultiProviderModelList` **之前**,为命中模型注入 `parameters`。利用 `modelParse.ts` 的 `parameters: model.parameters ?? knownModel?.parameters` 优先级——原始对象已带值即不被卡片覆盖。
- **DB 即时修复**:`UPDATE ai_models SET parameters = <aspectRatio schema jsonb> WHERE provider_id='newapi' AND id='gpt-image-2';`(代码修复只防未来再被覆盖,不回治当前已污染行)。
- **验证**:
  - 全仓 `pnpm type-check`(`tsgo --noEmit`)exit 0,无报错。
  - `npx vitest run src/providers/newapi/index.test.ts` → 84 passed + 1 pre-existing skip,含**新增用例** `should override gpt-image-2 parameters with the aspect-ratio schema instead of the pixel-resolution one`(断言传给 `processMultiProviderModelList` 的数组含 `parameters === gptImage2AspectRatioSchema`)。
  - DB SELECT 确认 `newapi`/`gpt-image-2` 行:`uses_aspect_ratio=t, uses_size=f`(其余 `openai` 行保持分辨率、`anthropic` 行 disabled,符合预期)。
- **已存记忆**:`custom-image-model-params-in-db.md` 已更新为"DB 改动非持久 + 代码层修复路径"。
